# 宽高隔离、拖动与聊天刷新保护

接续 `1e863d3`，本轮以用户最新实机反馈为准，取消此前“条幅变窄时整体缩小”的行为。以下规则取代之前两份条幅记录中的宽度比例缩放说明。

## 宽高只改变容器

条幅宽度和整体字号现在分别通过 `applyFloatingWidth`／`setBannerWidth`、`applyFloatingFont`／`setBannerFont` 更新。宽度接口只写条幅宽度；只有明确调整“条幅整体字号”才写内部显示比例。默认字号 11 对应 100%，字号 8 对应约 73%，与条幅宽度无关。条幅高度仅控制外框和列表可见空间。

保留单行标题及名称的剩余宽度分配。变窄时可见字符自然减少，放不下的名称省略；不会为了塞入更多文字而自动缩小内容。条幅内的字体、控件大小及外框尺寸保持各自设置，晚挂载或重载模块也不会重新按宽度计算字号。条幅尺寸预览不再向主界面写入无关的宽度变量或定制 class。

已逐项检查并通过实际调节分发函数回归：条幅、中控、主界面的宽高；预设／分支名称宽度；分组／条目高度；手柄宽高；按钮及悬浮球大小；双面板比例。它们均不会触发整个内容树的缩放。按钮本身的图标尺寸适配仍属于对应控件的尺寸规则。

## 拖动修复

- 悬浮球和中控将同一显示帧内的移动事件合并，保留最新合并采样及小数坐标。移动阶段继续只写外层 transform，不遍历内容、不测量布局、不保存状态。松手提交最后的坐标，并取消尚未绘制的帧。
- 中控按下后先记录几何信息，移动超过 4px 才开启拖动样式。单纯长按、轻微抖动及未移动的抬手不重定位、不保存位置。
- 长按悬浮入口唤出中控后，同一根手指不能继续拖动底下的悬浮球／条幅。中控及比例手柄禁止原生长按菜单；文本输入不受这些手柄规则影响。
- 中控和双面板拖动期间，视口变化及已排队的布局同步延后到手势结束处理。浮动入口的已排队视口回调也会重新检查手势状态，防止开始拖动后又改写边界。
- 三种手势处理取消、捕获丢失及窗口失焦；释放监听、取消绘制帧并结束主题交互占用。取消时不把事件中的零坐标写成新位置。中控使用起始设备方向保存，防止横竖屏变化把位置记入错误的设备方向。
- 双面板仍只拖动轻量分隔线，松手才调整两侧列表布局。冻结的 Aqua／Violet 材质、日夜视觉及原主题文件均未修改。

连续 240 次悬浮 pointermove 的运行回归验证了单次显示帧绘制；中控也覆盖了事件突发、最终坐标提交、未移动长按及取消。该结果衡量代码绘制次数，不等于实机 FPS。

## 聊天记录排查及处理边界

排查了工坊启动、草稿恢复、pagehide 清理、变量迁移、角色／聊天快照绑定及更新刷新入口，并只读对照了本机 SillyTavern 的 `script.js` 和 `scripts/st-context.js`。

没有在工坊活动代码中发现直接清空消息数组、删除聊天文件、向 `/api/chats` 写入，或调用聊天保存／清空接口的路径。工坊草稿写入自己的 sessionStorage；快照中的 `chats` 是绑定标识列表，不是聊天消息。未读取、修改或尝试覆盖用户聊天文件。

确认的风险是扩展更新检测和原生单独更新钩子都会自动刷新整个酒馆，原先没有检查当前聊天状态。现在两个入口统一在执行刷新前读取最新宿主上下文：已有聊天、已选角色（包括 ID 0）／群组、存在消息、生成中、输入中，以及宿主状态未知时，停止自动刷新并仅提示一次更新已完成，等用户在聊天保存后手动刷新。只有可确认无聊天且未输入时才保留自动刷新。

保护逻辑不会调用 `saveChat`、`saveMetadata` 或 `clearChat`，也不读取消息正文或新增聊天备份，避免把尚未载入的空状态当成需要保存的数据。没有新增轮询或拦截全局聊天网络请求。

**尚未确认手动刷新后聊天记录永久丢失的具体根因，也没有恢复已丢失记录。** 本轮修复的是已确认的更新刷新风险，不能视为已经证明所有实机丢失路径都被排除；其他扩展、服务端保存和原始聊天文件状态不在本轮模拟测试覆盖范围内。

## 统一实机验收

1. 只调条幅宽度，从窄到满屏再恢复，字号和内部按钮尺寸不变；再单独调整整体字号，外框不变。检查保存、取消和重开。
2. 平板长按唤出中控、长按中控顶部后拖动，检查无跳顶；中断触摸或横竖屏切换后，控件继续可操作。
3. 同时打开主界面、中控和条幅，检查悬浮球、中控及双面板分隔线的拖动和松手位置；主题切换后继续检查。
4. 在聊天中更新扩展，应提示更新完成并保留当前页面，不自动刷新。不要使用重要聊天主动复现丢失；新代码的首次载入放在聊天已保存后手动进行。

当前 Termux 无可用浏览器渲染实例，动画、触摸命中及实际流畅度仍需上述统一验收。
