## 实际根因与修复

**主界面日夜、跟随主题切换卡顿：** 上一轮为统一过渡，给条目、条目名称及中控大量控件增加了颜色动画。真实 Chromium 加载发布 CSS 和 600 条目 DOM 后，一次切换产生 4,800 个条目动画；先前少量条目的视觉测试验证了过渡，却没有覆盖这个随条目数量增长的开销。

本次直接收窄原有 `PMM_THEME_MOTION` 规则：保留面板、顶部、条幅、中控和悬浮入口的整体背景过渡，以及少量顶部功能区的颜色过渡。条目沿用既有规则，不再强制逐项补上颜色动画。600 条目回归中的条目动画数为 0。

同时消除三个重复样式计算来源：

- 主题事件曾直接传入 `refreshHeader(force)`，事件对象被误当成强制重新测量字体的参数；改为明确调用无强制参数的刷新。
- 将主题通知移到材质动画写入之后，避免订阅者在一批修改中间读取样式。
- 动画收尾和展开正文校色分别按“批量读取、批量写入、最后检查动画”组织，避免逐节点写入后立即触发样式计算。正文仍只调整文字颜色。

**平板悬浮球吸附越界：** 右侧吸附位置按最终 28px 把手计算，但实际宽度仍从悬浮球尺寸缓慢过渡。过渡期间，46px 悬浮球超出右边界 18px，96px 悬浮球超出 68px；横屏和竖屏均可复现。

本次让吸附尺寸和位置同时生效，保留圆角与图标透明度过渡。边界缓存同时考虑布局视口、文档可用宽高和可视视口，防止异常偏大的 `innerWidth` 或旧位置把入口送出屏幕。可视高度缩短只更新边界；横竖屏判定继续使用布局宽高，不把浏览器栏或键盘引起的可视高度变化误当成设备旋转，也不因此重算条幅自动宽度。

已复现并消除了悬浮球几何越界；测试中吸附前后页面滚动宽度没有增长，因此**没有直接复现浏览器界面被挤出空白的完整现象**。该现象仍需实际平板 Chrome 验收。
