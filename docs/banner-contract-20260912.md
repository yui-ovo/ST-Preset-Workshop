# 条幅名称、入口与宽度规则（2026-09-12）

本地版本：`2.98.2-page0x00.3`。基于已整合的作者 2.98.2；本轮不 commit、不 push。

本文取代旧文档中关于条幅半屏默认、半屏上限、名称省略号与顶部“条目”入口的规则。条幅高度、主界面布局和冻结材质不属于本轮变更。

## 实际原因及修复位置

- 原名称直接由原生 `<select>` 绘制，旧桌面/移动样式仍要求省略；之前只在后面叠加 `text-overflow:clip`，不能控制浏览器的原生选中项绘制。
- `dist/workshop-v3.02.js` 的真实 Vue 模板现在渲染名称字段、原生 select 和单行可见文本。select 保留真实值、完整选项、原有 change 处理和键盘/原生选择能力；显示文本不拼接省略号，显示层移除 `...`/`…`，不改写预设数据。
- `dist/workshop-floating-controller.js` 集中定义名称区域的 `min-width:0`、`white-space:nowrap`、`overflow:hidden`、`text-overflow:clip`，同时约束预设区域、字段、select 和可见文本。可见文本复用 select 的字体；旧全局裁切覆盖块、重复名称宽度规则和半屏 fallback 已删除。
- 原生桌面名称规则也改为 clip，并明确避开二改渲染区域，避免继续竞争。
- 删除控制器创建顶部“条目”按钮的代码和样式。点击铅笔左上方的原头部区域可展开/收起列表，右侧和下方空白不成为另一个入口；拖动、预设选择、分支选择、铅笔和条目列表功能保留。释放的空间由名称字段占用。

## 宽度唯一数据流

当前项目原本以 `mobile` / `desktop` 两组保存宽度；横竖屏 profile 保存悬浮位置，不另存宽度。本轮保留该机制。

1. 中控 profile 的 `values.floatingWidth` 是请求宽度；`customized.floatingWidth` 标识手动宽度。手动保存值不再被启动或横竖屏的 viewport clamp 截小。
2. 没有有效手动宽度，也没有本轮记录的自动默认时，值为待测量状态 `0`。它不表示实际渲染 0px，也不会回退半屏；尚未展开时中控显示“展开后自动计算”。
3. 第一次展开测量完整名称、仍可见的按钮、间距、内边距和边框，包含字号 zoom。计算结果限制到可视区域，回传给相同 profile 并记录 `bannerAutoWidth`。已确定的默认不因重新打开或重挂载而反复重置。按 2026-09-13 最新要求，仍处于自动模式时，名称、整体字号或横竖屏变化可以重新计算；手动模式完全不受这些变化影响。
4. `bannerSizing.width` 只接受中控的请求，`--pmm-mobile-floating-width` 只负责渲染该请求。最终 CSS `max-width` 负责视口限制，不能反向修改保存值。例如保存 920px 后进入 390px 视口，显示限于 390px，保存值仍为 920px。
5. 滑杆和有效数字输入按帧立即预览，不写保存值。保存后成为当前 profile 的手动宽度；取消恢复原值和自动/手动模式。只打开数值编辑器而未改动，不会转为手动宽度。
6. 恢复默认清除当前宽度组的手动状态和已计算默认，重新按当前完整内容测量一次；其他宽度组保留。与中控其他设置一致，保存后持久生效，取消可撤回本次重置。

原生条幅节点移除期间保留当前宽度模型；新节点挂载时直接应用该请求、自动/手动模式和 profile，不接受新节点上残留的旧宽度。渲染器本身重新加载时优先向现有中控 API 读取当前请求；没有中控实例时只读取同一份保存数据，不再从旧 DOM 宽度或半屏值推断用户意图。自动测量回调校验 profile、手动状态及测量前的请求宽度，拒绝过期结果。`bannerAutoContent` 保存自动计算时的名称和整体字号，重载同一内容时复用已算结果。
