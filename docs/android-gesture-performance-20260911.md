# 安卓交互与中控同步修复

- 中控保存会提交输入框当前数值并同步已打开的界面，修复旧滑杆预览覆盖后续数字输入的问题。输入法编辑尚未结束时保存也会读取当前值；保存失败后取消会恢复上次成功保存的设置。
- 双面板拖动改为逐帧调整实际比例，保留手指按下时的偏移；起拖距离降到 3px。松手采用最后一个位置，取消拖动恢复原比例和原样式。
- 中控同步复用控件节点，仅更新变化的数值与标签，减少重复 DOM 查询和写入。键盘编辑状态变化不再触发无关的悬浮界面重绘。
- 安卓触屏切换主题直接应用最终材质，省去临时过渡图层。折射玻璃、紫色的冻结色值及基准 CSS 保持原样。
- 再次打开已在屏幕外的中控时重新约束位置；主界面中控按钮增加透明触控范围，原按钮外观保持不变。

此前已发布版本中的缩放坐标修复、拖动期间延后后台扫描、拖动中临时停用背景模糊，以及首个有效移动立即跟随的逻辑继续保留。

验证覆盖：真实运行函数的保存、取消、输入法草稿和待执行滑杆帧；手机/平板完整悬浮模块；连续 240 个移动事件按帧合并；比例拖动取消与样式优先级恢复；缩放和可视区域偏移下的中控定位；40 个缓存控件重复同步 100 次不产生控件查询或写入；冻结材质哈希及作者功能回归。

请在安卓浏览器重点验证：

1. 从主界面打开中控，将它拖到屏幕中央和边缘，横竖屏切换后再次打开。
2. 拖动悬浮球和双面板比例，确认界面持续跟随手指；拖动后切换主题。
3. 解锁数值项，先拖滑杆再输入数字，直接点“保存更改”，确认数值和界面立即一致。分别测试中控宽高、字号、条幅、悬浮球大小和双面板比例。
4. 保存后继续修改再取消，确认恢复到最近一次保存值；关闭重开后核对保存结果。

`npm run check`、`npm run check:ui` 和 `git diff --check` 均通过。自动化使用 Node/VM 的 DOM 与事件模拟，尚未测量安卓浏览器的真实帧率和绘制耗时，本轮仍待实机验收。
